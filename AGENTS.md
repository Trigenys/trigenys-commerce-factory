# Engineering contract

This repository was generated by Trigenys AppFactory and follows the Trigenys Engineering OS (TEOS).

## Working rules

- Keep product logic out of generic infrastructure modules.
- Prefer small explicit boundaries over large multipurpose files.
- Treat security, failure handling and observability as design concerns, not release cleanup.
- Add dependencies only when they remove more complexity than they introduce.
- Every issue must have verifiable Proof of Done.
- Do not report work as complete until the relevant typecheck, build and tests pass.

## RAIDER

RAIDER means **Reusable, Agnostic, Idempotent, Durable / Non-regressive, Engineering-grade, Retroactive**. Apply the full [canonical RAIDER standard](docs/raider/RAIDER.md), including failure memory, reuse-first, scoped execution and brownfield adoption. Keep upstream authoritative; do not edit the mirrored copy locally.

[docs/RAIDER.md](docs/RAIDER.md) is the product register for the Commerce Factory MVP (risks, assumptions, issues, dependencies, evidence, results). For material changes, update the register alongside the canonical Definition of Done; it does not redefine RAIDER.

## Workflow

1. Read the task, past relevant failure memory, affected code, issues and documentation. For significant capabilities first assess **Adopt / Adapt / Learn / Build**.
2. For product/architecture/security/UX decisions, research relevant official standards and live competitors following [docs/research/SOURCES.md](docs/research/SOURCES.md); cite links and access dates. If offline, mark `RESEARCH_BLOCKED`.
3. Read [docs/agent-coordination/protocol.md](docs/agent-coordination/protocol.md). Assign one task owner, independent branches/worktrees and disjoint file scopes; otherwise serialize.
4. Make minimal, reversible changes. Do not overwrite another agent's unmerged edits.
5. Validate the affected gates from [docs/quality/QUALITY-GATES.md](docs/quality/QUALITY-GATES.md) in risk order; never claim unexecuted tests passed.
6. Write one dated `docs/walkthrough/<task-id>/<timestamp>__<agent>.md` for each nontrivial agent intervention, from [the template](docs/walkthrough/TEMPLATE.md).
7. Keep a written handoff with remaining risks and evidence.

## Constraints

- No production deployments, paid resources, secret modifications, destructive migrations or force pushes without approval.
- No fake citations, model claims, certifications or test results.
- Keep transport/persistence/provider adapters behind explicit boundaries.
- Consult and maintain [docs/engineering/lessons-learned.md](docs/engineering/lessons-learned.md) for significant failures/near misses and preventive controls.
- TEOS Skills are installed per user, not vendored here. Load only the Skills relevant to the task; for GitHub Actions, OIDC, deployment, backup or packaging work use the matching CI Skills and do not duplicate existing AppFactory reusable workflows.
- CI green, artifact published, deployed and production-smoke passed are separate claims requiring separate evidence.
- Cursor routing is advisory; subagent model IDs must be checked locally.
